# calculating — 약국 권리금 계산기

약국 권리금을 **실거래 회수배수 모델**로 산정하는 웹 계산기입니다.
"그 동네는 원래 그 정도"라는 감 대신, **어떤 요소가 얼마나 반영되어 그 금액이 나왔는지 설명할 수 있게** 만드는 것이 목표입니다.

- 조사원 3명 × 20케이스 = **60응답**으로 모델을 검증하고 계수를 보정했습니다 (범위 적중률 68% → **85%**)
- 계산 방식을 **v1(계단형) · v2(곡선형) · v3(정밀)** 세 버전으로 두고 결과를 비교할 수 있습니다
- Docker 로 바로 띄울 수 있습니다

> 데일리팜 약국 툴에서 권리금 관련 기능만 분리한 독립 프로젝트입니다.
> 관리·개발: **Yudev**

## 빠르게 띄우기

```bash
cp .env.example .env     # 포트·키 확인 후 수정
docker compose up -d --build
```

- 웹: http://localhost:8090 (`.env` 의 `WEB_PORT`)
- DB: localhost:3318 (`.env` 의 `DB_PORT_HOST`) — 컨테이너 내부에서는 `db:3306`
- 스키마는 DB 최초 기동 시 `schema.sql` 이 자동 적용됩니다.

**로그인이 없습니다.** 권리금 도구는 모두 공개라 바로 쓸 수 있고,
관리자 페이지만 `.env` 의 `DASHBOARD_PASSWORD` 로 보호됩니다 (인증하면 사이드바에 관리자 메뉴가 나타납니다).

원본에 있던 권리금 구성(바닥·영업·시설 분해), 매물 비교, 권리금 계산 곡선형은 이 프로젝트에서 제외했습니다.

## 계산 모델

권리금 = **월 환산수익 × 지역 회수개월수 × 조제료 규모 계수**, 여기에 저수익 임계 할인과
의사 고령 할인, 지역 피드백·설문 보정을 적용합니다. 핵심 구현은 `src/config.php` 의 `gwBaseQuote()` 한 곳에 있고
시세·계산·구성·매물 비교가 모두 이 함수(또는 동일 계산의 JS 포트)를 씁니다.

기준값은 2026-09 적정성 조사(조사원 3명 × 20케이스 = 60응답)를 반영한 상태입니다
— 지역 회수개월수 전 지역 ×1.15, 조제료 1,000만원 미만 규모 계수 0.50.

## 접근 제어

원본의 회원 등급 체계(로그인·승인)는 걷어냈습니다. `src/auth.php` 가 호출부 호환용 껍데기로 남아
`authGuard()` 는 항상 통과시키고 `authLevel()` 은 관리자 비밀번호 인증 여부만 반환합니다.
다시 로그인 기반으로 돌리려면 이 파일만 교체하면 됩니다.

지역 파트너(컨설팅·중개사) 소개 기능도 제거했습니다 — 관련 페이지·테이블 모두 없습니다.

## 버전 표기

권리금 계산은 고도화 순서대로 세 버전을 둡니다. 이름은 모두 `권리금 계산`으로 통일했습니다.

- **v1 (계단형)** — 조제료를 5개 구간으로 나눠 구간별 고정 계수. 설명이 쉬운 대신 경계에서 금액이 한 번에 뜁니다.
- **v2 (곡선형)** — 구간 사이를 선형보간. 경계에서 튀지 않습니다. 나머지 계산(지역 회수개월수·보정)은 v1과 동일합니다.
- **v3 (정밀)** — v1 시세를 기초로 상권·병원 의존도·잔여 임대차·임대료 부담을 반영하고,
  **공공데이터포털에서 해당 지역의 병·의원 수·약국 수를 조회해 결과에 표시**합니다.
  약국 1곳당 병·의원 수를 전국 평균(1.7곳)과 비교해 처방 유입 여력도 판정합니다. AI 상권·리스크 분석과 개국 자금 계획 포함.

v3의 의료기관 실측에는 `.env` 의 `DATA_GO_KR_KEY` 가 필요합니다. 키가 없으면 그 자리에
'미조회' 안내가 표시되고 나머지 계산은 정상 동작합니다.

## 운영 메모

- 소스는 `./src` 가 컨테이너에 마운트되어 **수정하면 새로고침만으로 반영**됩니다. 이미지에 굽고 싶으면 compose 의 volumes 에서 `./src` 줄을 빼세요.
- `.env` · `.sql` · `.md` 는 Apache 설정으로 웹 노출이 차단됩니다.
- PHP 오류는 화면에 표시하지 않고 컨테이너 로그로 보냅니다: `docker compose logs -f web`

## 사용한 외부 API

| API | 제공 | 쓰임 | 필수 여부 |
|---|---|---|---|
| 병·의원 찾기 | 국립중앙의료원 (공공데이터포털) | 행정구역 내 병·의원 수 — 처방 유입 여력 판정 | 선택 (`DATA_GO_KR_KEY`) |
| 약국 찾기 | 국립중앙의료원 (공공데이터포털) | 행정구역 내 약국 수 — 경쟁 밀도 판정 | 선택 (`DATA_GO_KR_KEY`) |
| 상권정보 | 소상공인시장진흥공단 (공공데이터포털) | 좌표 반경 500m 상가 업소 수·업종 분포 | 선택 (`DATA_GO_KR_KEY`) |
| 로컬 (주소 → 좌표) | 카카오 | 주소를 좌표로 변환해 상권 조회에 연결 | 선택 (`KAKAO_REST_KEY`) |
| 우편번호 서비스 | 카카오(다음) | 주소 검색 UI | 불필요 (프런트 스크립트) |
| Gemini | Google | 상권 분석·리스크 평가·협상 전략 서술, 입력값 검증 | 선택 (`GEMINI_API_KEY`) |

키가 없으면 해당 기능만 건너뛰고 **권리금 계산 자체는 정상 동작**합니다.
AI 에는 확정된 산출치를 넘겨 서술만 맡기고 **금액을 재계산시키지 않습니다** — 같은 입력에 같은 결과가 나와야 협상 근거로 쓸 수 있기 때문입니다.

## 로드맵

### 1단계 — 표본 확보 (단기)

현재 모델은 **60응답**으로 보정했습니다. 신뢰 구간을 좁히려면 표본이 더 필요합니다.

- [ ] 적정성 설문을 조사원·협회 채널로 배포해 **지역별 30건 이상** 확보 → 지역 보정 자동 가동
- [ ] 조사자 간 편차가 컸던 **지방 중소도시** 집중 조사 (현재 3명 응답이 서로 엇갈림)
- [ ] **월 조제료 3,500만원 이상 대형 구간** 케이스 추가 — 현재 검증 표본 0건이라 계수가 미검증 상태

### 2단계 — 모델 정교화 (중기)

- [ ] v1·v2 중 실무에 맞는 쪽을 데이터로 결정하고 기본값 확정
- [ ] **병원 의존 구조를 수치화** — 현재는 3단계 선택이지만, 처방 상위 병원 비중을 입력받아 연속값으로 반영
- [ ] 의사 연령 할인을 실제 폐업 통계와 대조해 계수 재산정
- [ ] 저수익 임계점(월 700/1,000만원)을 지역별로 분리 — 현재는 전국 단일 기준
- [ ] **실거래 데이터 확보 경로 마련** — 현재는 수익 기반 추정. 중개사·컨설팅 협력으로 체결가를 모을 수 있으면 모델 검증 축이 하나 더 생김

### 3단계 — 활용 확장 (장기)

- [ ] **권리금 구성 분해** 재도입 — 바닥·영업·시설로 나눠 협상 단위로 제시 (원본에 구현되어 있던 기능)
- [ ] **매물 비교** 재도입 — 받은 매물 여러 건을 같은 모델로 평가·순위화
- [ ] 산정 결과 **PDF 리포트** 출력 — 협상 자리에 들고 갈 수 있는 형태
- [ ] 지역·규모별 **시세 추이 대시보드** — 설문·피드백이 쌓이면 시계열로
- [ ] 개국 자금 계획과 **대출 상품 연계**

### 운영 과제

- [ ] 공공데이터포털·카카오 키의 운영 계정 전환 (현재 개발 키)
- [ ] `gemini-flash-latest` 응답 지연(평균 10초) 대응 — 점검 타임아웃 조정 또는 예비 모델 기본화
- [ ] 계수 변경 이력 관리 — 언제 왜 바꿨는지 추적 가능하게

## 한계

- **실거래가 조회가 아닙니다.** 공개된 약국 권리금 실거래 데이터베이스는 존재하지 않습니다. 수익 구조에 기반한 **추정 모델**입니다.
- 실제 거래는 1인약국 여부·병원 안정성·건물 형태·임대차 조건에 따라 **±30% 수준까지** 달라질 수 있습니다.
- 검증 표본이 조사원 3명·20케이스 기준이며, 대형 구간은 아직 미검증입니다.
