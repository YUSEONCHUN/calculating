## 1. 개발 목적 및 배경

### 신규 개국 약사가 겪는 문제

약국 인수·개국은 대부분 **생애 한두 번**입니다. 그런데 이때 오가는 권리금은 수천만 원에서 수억 원입니다.
**가장 큰 금액이 걸린 결정을, 가장 경험이 적은 상태에서** 내려야 합니다.

- 중개사가 권리금 3억을 제시한다 → 비싼지 싼지 판단할 기준이 없다
- 물어보면 "그 동네는 원래 그 정도", "조제료 몇 개월치면 적당하다"
- **그 '몇 개월치'가 왜 그 숫자인지는 아무도 설명하지 못한다**

업계의 감은 틀린 게 아닙니다. 다만 **수치화되지 않아 검증할 수도, 물려받을 수도 없습니다.**

### 왜 일반 권리금 계산기로는 안 되는가

일반 상가는 `월 매출(또는 순이익) × 일정 개월수` 로 업종을 가리지 않고 계산합니다. 약국은 전제가 다릅니다.

| 구분 | 일반 상가 | 약국 |
|---|---|---|
| 수익의 원천 | 매출 전체 | **조제료(처방 건수)가 핵심** |
| 수요의 성격 | 유동인구·상권 | **인근 병·의원의 처방**에 종속 |
| 입지 대체성 | 비슷한 자리로 이전 가능 | **병원 앞 자리는 대체 불가** |
| 핵심 리스크 | 상권 쇠퇴 | **병원 이전·폐업** 한 번에 수익 소멸 |
| 시설 | 범용 인테리어·집기 | **조제 전용 설비**(ATC·조제대·약장) |
| 재고 | 비중 낮음 | **금액이 크고 유효기간 리스크** |

→ **구성 요소가 다르면 가중치도 달라야 합니다.** 일반 계산기를 쓰면 소형은 과대평가, 문전 대형은 과소평가됩니다.

### 이 프로젝트가 하려는 것

> 감을 부정하는 게 아니라, **감이 담은 판단을 수식과 계수로 옮겨 누구나 쓰고 검증할 수 있게** 만드는 것

## 2. 개발 히스토리 — v1에서 v3까지

```
0단계   현장의 감을 숫자로        주변 약사 대상 20케이스 조사 → 오차 측정
  ↓
v1      단순 계산식 + 구간 배율    결과는 나오지만 경계에서 금액이 절벽처럼 튐
  ↓
v2      절벽 구간을 완만하게       구간 사이를 선형보간하는 식 도입
  ↓
v3      외부 데이터 결합           Gemini + 공공데이터·카카오 API 연동
```

### 0단계 — 계산식보다 '정답지'를 먼저 만들었다

1. 가상의 약국 조건 **20개 케이스**를 지역(5개 권역)·규모별로 구성 (조건은 랜덤·반올림)
2. 각 케이스에 **계산기 산출 금액을 함께 적어** 표로 작성
3. 주변 약사에게 전달해 **"당신이 보는 적정 권리금"** 을 직접 기입받음

> 계산 결과를 숨기지 않고 같이 보여준 것이 핵심입니다.
> 백지에 적게 하면 답이 흩어지지만, 모델가를 옆에 두면 "높다/낮다" 판단이 함께 나옵니다.
> 처음부터 **오차를 재는 것**이 목적이었기 때문입니다.

### 0단계 결과 — 모델 선택

| 계산 방식 | 응답이 산출 범위 안에 든 비율 |
|---|---|
| 월 매출총이익 × 12개월 (일반 상가식) | 7 / 40 (18%) |
| 지역 회수개월수 × 조제료 규모 계수 | **32 / 40 (80%)** |

일반 상가식은 지역·규모·저수익을 전부 상수로 취급해 **대형은 응답의 60~70% 수준으로 과소평가**, **소형은 2.5~4배로 과대평가**했습니다.

### v1 — 단순 계산식에 구간 배율

```
권리금 = 월 환산수익 × 지역 회수개월수 × 조제료 규모 계수
```

| 월 조제료 | 계수 |
|---|---|
| 1,000만원 미만 | 0.50 |
| 1,000 ~ 2,500 | 1.00 |
| 2,500 ~ 3,500 | 1.15 |
| 3,500 ~ 5,000 | 1.25 |
| 5,000 이상 | 1.35 |

**문제 — 경계에서 그래프가 끊겼다**

같은 조건에서 월 조제료만 1만원 차이:

| 월 조제료 | 계수 | 적정 호가 |
|---|---|---|
| 999만원 | 0.50 | **1억 2,352만원** |
| 1,000만원 | 1.00 | **2억 4,725만원** |

| 경계 | 계수 변화 | 금액 점프 |
|---|---|---|
| 1,000만원 | 0.50 → 1.00 | **+100%** |
| 2,500만원 | 1.00 → 1.15 | +15% |
| 3,500만원 | 1.15 → 1.25 | +9% |
| 5,000만원 | 1.25 → 1.35 | +8% |

구간을 나눈 편의가 그대로 결과의 왜곡이 됐습니다. 쓰는 사람에게는 **"숫자를 조금 바꿨는데 결과가 확 변한다"는 신뢰 문제**입니다.

### v2 — 절벽을 완만하게

구간은 유지하되 **사이를 직선으로 이어** 계수가 연속적으로 변하게 했습니다. 기준점 값은 v1과 동일하므로 **검증으로 얻은 기준은 보존**됩니다.

```js
lerp(x, x0, y0, x1, y1) = y0 + (x - x0) / (x1 - x0) × (y1 - y0)

p ≤ 1,000         →  0.50 + (p / 1,000) × (1.00 - 0.50)
1,000 < p < 2,500 →  lerp(p, 1000, 1.00, 2500, 1.15)
2,500 < p < 3,500 →  lerp(p, 2500, 1.15, 3500, 1.25)
3,500 < p < 5,000 →  lerp(p, 3500, 1.25, 5000, 1.35)
p ≥ 5,000         →  1.35
```

| 경계 | v1 점프 | v2 점프 |
|---|---|---|
| 1,000만원 | +100% | **+0.05%** |
| 2,500만원 | +15% | **+0.01%** |
| 3,500만원 | +9% | **+0.01%** |
| 5,000만원 | +8% | **+0.00%** |

**그런데 v2가 더 정확하지는 않았습니다.** 같은 60응답으로 돌려 보니 경계 점프는 사라졌지만 적중률은 떨어졌습니다.

| 모델 | 범위 적중 | ratio 중앙값 | 소형 구간 | 일반 구간 |
|---|---|---|---|---|
| v1 계단형 (보정 후) | **51/60 (85%)** | **0.999** | **0.992** | 1.006 |
| v2 곡선형 (보정 후) | 42/60 (70%) | 0.926 | **0.525** | 0.943 |

차이는 전부 **소형 구간**에서 나왔습니다. v2는 0 → 1,000만원을 직선으로 잇기 때문에 조제료 800~900만원이면 계수가 0.90~0.95가 되는데,
v1의 0.50은 **소형 케이스 응답으로 직접 보정한 값**이기 때문입니다. 소형 표본이 3케이스 9응답뿐이라 지금 데이터로는 결론을 낼 수 없습니다.

→ **v1을 기본값으로 유지**하고 v2는 비교용으로 남겼습니다. v3의 기초 산출도 v1 엔진을 씁니다.
**매끄러운 식이 정확한 식은 아니었고, 검증 데이터가 있었기에 배포 전에 알 수 있었습니다.**

### v3 — 외부 데이터 결합

v1·v2는 입력한 숫자만으로 계산합니다. 그러나 실제 판단에는 **사용자가 입력할 수 없는 정보**가 필요합니다.

- **공공데이터포털** — 해당 지역 병·의원 수·약국 수 조회 → 약국 1곳당 병·의원 수를 전국 평균과 비교
- **카카오** — 주소 → 좌표 변환, 반경 500m 상권 업소 분포
- **Gemini** — 상권 분석·리스크 평가·협상 전략 서술, 입력값 검증
- **개국 자금 계획** — 권리금 + 보증금 + 인테리어 + 초기 재고 + 예비 운전자금

v3는 조사 응답과 1:1 대조가 불가능합니다(매물 상세 조건은 조사지에 없던 입력). 그래서 네 가지로 검증했습니다.

| 검증 항목 | 결과 |
|---|---|
| 기초 산출 일치 | v1과 **동일** — 같은 `gwBaseQuote()` 호출, 화면에 'v1 입력 기준 환산' 행으로 노출 |
| 재현성 | 같은 입력 → **같은 금액** (계산은 PHP에만, `temperature: 0`) |
| 실측 정확도 | 강남구 조회 → 병·의원 3,119곳 / 약국 515곳 = 6.1:1 (전국 평균 1.7:1의 3.6배) |
| 장애 내성 | 키 없음·API 오류 → '미조회' 후 계산 계속 / 기본 모델 지연 → 예비 모델 자동 전환 |

### 버전 비교

| 항목 | v1 | v2 | v3 |
|---|---|---|---|
| 기초 산출 | 회수배수 (계단형) | 회수배수 (곡선형) | **v1과 동일** |
| 60응답 범위 적중 | **51/60 (85%)** | 42/60 (70%) | v1과 동일 |
| 입력 변수 | 5개 | 5개 | 15개+ |
| 외부 데이터 | 없음 | 없음 | 병·의원·약국·상권·AI |
| 용도 | **기본 시세** | 경계 비교 | 매물 실사·협상 준비 |

## 4. 사용한 API와 수집 데이터

| API | 제공 기관 | 가져오는 데이터 | 쓰임 |
|---|---|---|---|
| 병·의원 찾기 | 국립중앙의료원 | 시군구·동 단위 병·의원 수, 주요 의료기관명 | 처방 유입 여력 판정 |
| 약국 찾기 | 국립중앙의료원 | 시군구·동 단위 약국 수 | 경쟁 밀도 판정 |
| 상권정보 | 소상공인시장진흥공단 | 좌표 반경 500m 상가 업소 수·업종 분포 | 상권 성격 파악 |
| 로컬 (주소→좌표) | 카카오 | 위경도 좌표 | 상권 조회 연결 |
| 우편번호 서비스 | 카카오(다음) | 주소·행정구역 | 주소 입력 UI |
| Gemini | Google | — (생성) | 상권·리스크 서술, 입력 검증 |

### 실측 데이터를 어떻게 쓰는가

**약국 1곳당 병·의원 수**를 전국 평균(1.7곳)과 비교해 3단계로 판정합니다.

| 조회값 | 판정 |
|---|---|
| 평균의 1.2배 이상 | 처방 유입 여력이 평균보다 넉넉한 편 |
| 평균 ±20% 이내 | 전국 평균과 비슷한 수준 |
| 평균의 0.8배 이하 | 약국이 상대적으로 많아 경쟁이 센 편 |

> "그 동네 약국 많아?"라는 질문을 **숫자로 답하게** 만든 것입니다.

### 키 발급 — 세 곳에서 받는다

세 키 모두 무료 등급으로 충분하고, **없으면 해당 기능만 건너뛰고 권리금 계산은 정상 동작**합니다.

| 키 | 어디서 | 받는 절차 |
|---|---|---|
| `DATA_GO_KR_KEY` | 공공데이터포털 (data.go.kr) | 가입 → **병의원 찾기 / 약국 찾기 / 상가(상권)정보** 세 서비스 각각 활용신청 → 마이페이지에서 **일반 인증키 (Decoding)** 복사 |
| `KAKAO_REST_KEY` | 카카오 개발자센터 | 애플리케이션 추가 → **앱 키 → REST API 키** 복사 (카카오 로그인·플랫폼 설정 불필요) |
| `GEMINI_API_KEY` | Google AI Studio | **Get API key** → 프로젝트 선택 후 키 생성 |

> ⚠ 공공데이터포털은 **Encoding 키가 아니라 Decoding 키**를 써야 합니다. 코드가 쿼리를 만들며 키를 인코딩하므로
> 이미 인코딩된 키를 넣으면 이중 인코딩되어 인증 오류가 납니다. 승인 직후 키 반영까지 몇 분~1시간 걸릴 수 있습니다.
> 단계별 절차는 [README의 '키 발급 방법'](../README.md#키-발급-방법) 참고.

### 설계 원칙 — AI는 계산하지 않는다

수치 계산은 전부 서버에서 끝내고, AI에는 **확정된 산출치를 넘겨 서술만** 맡깁니다.
**같은 입력에 같은 결과가 나와야 협상 근거로 쓸 수 있기 때문**입니다.

## 5. 로드맵

### 1단계 — 표본 확보 (단기)

현재 모델은 60응답 기준입니다. 신뢰 구간을 좁히려면 표본이 더 필요합니다.

- 적정성 설문을 조사원·협회 채널로 배포해 **지역별 30건 이상** 확보 → 지역 보정 자동 가동
- 조사자 간 편차가 컸던 **지방 중소도시** 집중 조사
- **월 조제료 3,500만원 이상 대형 구간** 케이스 추가 (현재 검증 표본 0건)

### 2단계 — 모델 정교화 (중기)

- v1·v2 중 실무에 맞는 쪽을 데이터로 결정
- **병원 의존 구조 수치화** — 처방 상위 병원 비중을 입력받아 연속값으로 반영
- 의사 연령 할인을 실제 폐업 통계와 대조해 재산정
- 저수익 임계점을 **지역별로 분리** (현재 전국 단일 기준)
- **실거래 데이터 확보 경로** — 중개사·컨설팅 협력으로 체결가를 모으면 검증 축이 하나 더 생김

### 3단계 — 활용 확장 (장기)

- **권리금 구성 분해** 재도입 — 바닥·영업·시설로 나눠 협상 단위 제시
- **매물 비교** 재도입 — 여러 매물을 같은 모델로 평가·순위화
- 산정 결과 **PDF 리포트** — 협상 자리에 들고 갈 형태
- 지역·규모별 **시세 추이 대시보드**
- 개국 자금 계획과 **대출 상품 연계**

### 운영 과제

- 공공데이터·카카오 키 운영 계정 전환
- `gemini-flash-latest` 응답 지연(평균 10초) 대응
- 계수 변경 이력 관리 (언제·왜 바꿨는지 추적)

## 6. 한계와 전제

- **실거래가 조회가 아닙니다.** 공개된 약국 권리금 실거래 DB는 존재하지 않습니다. 수익 구조 기반 **추정 모델**입니다.
- 실제 거래는 1인약국 여부·병원 안정성·건물 형태·임대차 조건에 따라 **±30% 수준까지** 달라질 수 있습니다.
- 검증 표본은 조사원 3명·20케이스이며, 대형 구간은 미검증입니다.
